Investigated TIN/TRIM 2008.04 and 2013.00 Standard. The user inventoried the
interfaces, supplied screenshots, and generated initial comparison inputs.
Later computer-use checks selected the Damage menu entries and captured TIN's
generated TRIM.IN files. Direct TRIM runs tested the resulting calculation codes.
Original installation documentation was used, rather than earlier cached TRIM

2. INPUT INVENTORY

Incident ion:
  Symbol, name, atomic number, mass (amu), total energy (keV), incidence angle.
  Confirmed angle range: 0 to 89.9 degrees; zero is normal incidence.
  Periodic Table (PT) selection is available. Symbol/name/number identify the
  same element. Help recommends the most abundant isotope for projectile mass.

Target hierarchy:
  Target -> layers -> components -> component damage energies.

Each layer:
  Layer name; width; width unit (Angstrom, micrometre, mm, cm, m, km);
  density (g/cm3); compound correction; gas checkbox.

Each component in a layer:
  Symbol, name, atomic number, weight (amu), atomic stoichiometry, displayed
  atomic percentage, displacement energy, lattice-binding energy, and
  surface-binding energy (all three energies in eV).
  The percentage field is greyed out and follows entered atomic stoichiometry.

Target controls:
  Add Layer, Add Element to Layer, Compound Dictionary, PT, delete layer,
  delete component. Deletion and general navigation are not central to the
  intended input-building workflow.

Density:
  The user observed automatic recalculation when adding an element to a layer.
  No separate Auto checkbox was visible. Whether a manual density value survives
  subsequent composition edits has not been checked.

Damage energies:
  Disp: energy needed for a recoil to escape its original site by more than one
        atomic spacing; otherwise it is assumed to return and lose energy to phonons.
  Latt: energy lost to phonons when a target recoil leaves its lattice site.
  Surf: energy needed to leave the target surface, important for sputtering;
        this is not simply a chemical bond dissociation energy.
  Separate entries for the same element allow different damage properties in
  different layers, e.g. Si in SiO2 versus Si in a silicon substrate.

Special parameters:
  Calculation name; stopping-power version (only SRIM-2008 observed in both
  2008 and 2013); autosave interval in ions; total ion count; random seed;
  minimum/maximum plotting-window depths in Angstrom.

Requested output controls:
  Ion Ranges; Backscattered Ions; Transmitted Ions/Recoils; Sputtered Atoms;
  Collision Details (checkbox); Special EXYZ File Increment (numeric, eV).
  EXYZ records positions at approximate energy-loss intervals, not spatial steps.

Actions:
  Save Input & Run TRIM; Clear All; Restore Last TRIM Data;
  Calculate Quick Range Table; Resume Saved TRIM Calculation.
  The 2008 interface also displays Use TRIM-96 (DOS); its operation was excluded.
  Later computer-use inspection showed Resume as a button in 2013, whereas it
  is a checkbox in 2008; the 2013 window did not display the 2008 DOS checkbox.
  These action-control presentation differences do not alter the core field inventory.

3. DAMAGE / CALCULATION-TYPE INPUT CODES

Codes below are numbers written to TRIM.IN, not saved-state runtime numbers.
The Damage menus are one-based: every observed menu position equals its input code.

Calculation                                  2008 input    2013 input
Ion distribution, quick damage                    1             1
Detailed ion calculation, full cascades            2             2
Surface sputtering / monolayer collision steps     3             3
Specified ion energy/angle/depth, quick damage     4             4
Specified ion energy/angle/depth, full cascades    5             5
Recoil cascades from neutrons/etc., quick damage   6             8
Recoil cascades from neutrons/etc., full cascades  7             6
Recoil cascades plus monolayer steps               -             7

2013 reverses the wording of option 3 to Monolayer Collision Steps / Surface
Sputtering, calls quick damage KP (Kinchin-Pease), and revises the text of
specified-ion and recoil selections. The key change is the final three options.

Modes 4+ require TRIM.DAT. Ion modes consume initial particle conditions;
neutron/electron/photon modes consume externally generated target recoil events.
TRIM does not calculate the initiating neutron/electron/photon transport itself.
The added monolayer recoil mode is documented as useful for thin targets or
low energies.

Saved-state distinction:
  2008 TDATA.sav preserves input codes 1-7 in the tested cases.
  2013 input 1-5 -> saved runtime 1-5.
  2013 input 6   -> saved runtime 7 (full recoil cascades).
  2013 input 7   -> saved runtime 8 (monolayer recoil cascades).
  2013 input 8   -> saved runtime 6 (quick recoil damage).
Do not interpret a TDATA.sav cascade number using the 2013 TRIM.IN menu mapping.

SUPPORTED SCOPE - USER DECISION:
  2008: intended input codes 1-7 only.
  2013 Standard/Pro: intended input codes 1-8 only.
  Exclude code 0 for both and code 8 for 2008, despite their executable behavior.

4. BASIC PLOT INPUT CODES

Both versions expose the same six choices for every Damage menu entry.
Direct tests confirmed identical plot meanings in 2008 and 2013:

Menu position   TRIM.IN PlotType   Result
     1                 0          XY: ions and recoils (Depth vs. Y-Axis)
     2                 1          XZ: ions and recoils (Depth vs. Z-Axis)
     3                 2          XY: ions only (Ion Trajectories)
     4                 3          YZ: transverse ions/recoils (Transverse View)
     5                 4          All four views
     6                 5          No graphics; no newly saved plot images

2008's third label is wrong: Recoil Distribution only (No Ions) projected on
Y-Plane. The actual plot is XY Ions Only / Ion Trajectories. 2013 corrects the
label to Ion Distribution only (no recoils) projected on Y-Plane, agreeing with
both executable behavior and the plot help. This discrepancy is resolved.

5. TEST METHOD AND LIMITS

Plot tests: 12 isolated runs, six codes for each version, each completed 100 ions.
Baseline: Ar, Z18, mass 39.962 amu, 50 keV, zero incidence angle; one 3000 Angstrom
solid Si layer, density 2.3212 g/cm3, mass 28.086 amu, stoichiometry 1, correction
1; Disp/Latt/Surf = 15/2/4.7 eV; seed 12345; no optional output files.
PlotType 4 saved TP0.bmp through TP3.bmp; PlotType 5 produced no new plot images.
User screenshots and generated inputs confirmed third plot -> code 2 in both.
TIN wrote density 2.3212 rather than the originally requested 2.32; actual file
values were preserved. Ordinary plot comparisons establish display meaning,
not cross-version numerical equivalence.

Damage tests: all 15 intended version/mode combinations completed one ion/event,
with direct input seed 12345 and no graphics. Modes 1-3 used the Ar-Si baseline.
Modes 4+ used a synthetic TRIM.DAT: ten header lines; one five-character event
name T0001; Si Z14, 1000 eV, depth 100 Angstrom, Y=Z=0, direction cosines 1,0,0;
ASCII CRLF and terminal EOF byte 0x1A. The original installations were untouched.
The 2008 GUI mode-2 mapping uses the earlier user-generated capture; remaining
captures were made through computer use. Tests are operational one-event checks,
not validation of physics accuracy or complete file-format/boundary coverage.

Dialogs / automation:
  TIN saves TRIM.IN before its TRIM.DAT warning. Cancel at that warning preserves
  the input without starting TRIM.
  Direct batch runs used TRIMAUTO=1, but some modes still required UI handling.
  2008 codes 6/7 and 2013 codes 6/8 asked whether to save each cascade in
  COLLISON.txt. No was selected. Initial 2008 timeouts were these prompts,
  not demonstrated calculation failures.
  2013 codes 5-8 required acknowledgment of the End of TRIM.DAT calculation dialog.
  Complete unattended execution of every mode is therefore not established.

7. DOCUMENTATION QUALIFICATIONS AND REMAINING WORK

Manuals: 2008 HELP - TRIM Setup and Input.pdf; 2013 HELP - TRIM Input.pdf.
Relevant installed SRIMHelp files include Help1.rtf (types), help10.rtf (plots),
help9.rtf (target), help18.rtf (stopping version), help7.rtf (angle),
helpTR16.rtf (autosave), help66.rtf (EXYZ), and Help15.rtf (recoil-event input).

The manuals/help retain older material: stopping help and setup screenshots
refer to 2003 despite the observed 2008 selector. Some TRIM.IN example headings
list only seven modes, even in 2013. DOS help contradicts its visible 2008
control. Manual energy ceilings conflict: 2 GeV/amu in the introduction versus
10 GeV/amu in the ion-input section. Do not turn those into verified limits.

Documented, not boundary-tested: 8 layers; up to 12 target elements per layer;
ion count to 9999999; integer seed 0-999999999; autosave 1-32000 ions, with higher
values described as disabling autosave. Exact defaults and validation rules
remain to be verified. Target help's historical Auto checkbox was not observed;
the user instead observed automatic density recalculation on element addition.
Stoichiometry is normalized internally. Plot depth defines the 100 depth bins
for averaged stored data, not merely the displayed viewport.

TIN field inventory, plot meanings, and intended Damage input mapping are complete
for this investigation. Next work belongs to TRIM input/runtime investigation:
  - Complete TRIM.IN and TRIM.DAT formats, conversions, limits and validation.
  - Runtime dependencies, working-directory requirements and clean isolation.
  - Output-option behavior, formats, and provenance.
  - Batch dialogs, lifecycle, interruption and resume-state requirements.
  - Numeric boundary checks and unresolved density-edit behavior if needed.
Implementation has not been proposed or approved by this investigation.
