## No-response save-requirement investigation

The user subsequently requested determining which cases actually need the save-button pathway. Twelve report-only 100-to-200 continuations tested ion-full and specified-ion-full on 2008, 2013 Standard and Pro, each with autosave 200 and autosave 10000. Four preserved parents were reused unchanged and two fresh event parents were created. Every probe stopped its owned job at the observed 200-ion completion dialog without sending any completion acknowledgment or Save response.

All six autosave-200 cases already had complete recoverable final checkpoints in `SRIM Restore`. All six autosave-10000 cases had no final checkpoint there; their staged restore source still contained the original current count 100, not the completed 200. All event prefixes and complete staged event inputs remained unchanged, as did all parent records, installations and settings. These intentional report-only popup stops remain failed lifecycle records; checkpoint availability is the diagnostic result, not a historical success override.

Evidence: `.cache/trim-sav-live/no-save-20261022T115211Z-dc08d244/report.json`; additional location/input checks are in the adjacent `checkpoint-locations.json`. No production implementation changed in this investigation. It establishes the measured rule for these two modes on the three installations, not universal mode coverage or atomic/scientific certification.

Save is therefore not inherently required by ordinary versus event continuation or by version. It is unnecessary when a valid final checkpoint already exists. With no autosave covering the final count, obtaining that final checkpoint requires an explicit saving mechanism or an explicitly selected final-aligned autosave schedule. The approved implementation uses checkpoint readiness as the condition and must not silently change requested autosave settings. `TRIM_CHECKPOINT_FIRST_PROPOSAL.md` now specifies this shared rule and supersedes the unapproved event-only proposal. The user explicitly approved the complete shared proposal. Its checkpoint-first policy/report version-4 implementation replaces the old event-save route; verification is recorded below. Fresh TRIM and SR calculation flows keep their existing normal completion paths; they do not call the TRIM continuation Save selector.
